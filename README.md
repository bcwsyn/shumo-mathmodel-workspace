# 高质量数学建模项目

本仓库用于接收一道数学建模题目及其附件，按 G0–G7 人工审批流程完成题意分析、建模设计、生产级代码、正式实验、学术图表、可编辑论文和最终完整交付包。新项目使用 XeLaTeX 源码与 PDF，既有 DOCX/Typst 项目保留原主稿。

## 默认目标

- 默认模式是“高质量完整建模”，不是受历史年度 AI 条款约束的简化稿。
- AI 作为优秀数学建模团队完成全流程；用户在每个阶段检查方向并决定修改或继续。
- 竞赛名称默认只决定模板、语言和页面结构。只有用户明确要求“直接参赛并做当年合规验收”时，才另行处理外部提交规则。
- 质量以数学正确性、题目针对性、方案比较、实验充分性、结论证据、图表质量、写作水平和可复现性衡量。

## 使用方式

提供题面和附件，并说明竞赛类型、论文语言或特殊偏好即可。入口工作流会创建 projects/<YYYYMMDD>-<题目短名>/。

随后逐阶段提交：

| 阶段 | 确认内容 |
| --- | --- |
| G0 | 材料盘点、题意、子问题、歧义和数据风险 |
| G1 | 候选模型比较、最终数学方案和验证计划 |
| G2 | 最小可行代码、基线结果和异常检查 |
| G3 | 正式实验、对比、灵敏度/稳健性和数据图表 |
| G4 | 技术路线图、流程图等非数据图示，或批准跳过 |
| G5 | 论文大纲、核心论点、公式和图表放置 |
| G6 | 完整论文源文件、引用和数值核对 |
| G7 | 预览 PDF 的内容与逐页版式 |
| Final | 代码复验、质量证据、最终 PDF 与完整交付文件夹 |

每阶段收到“批准 Gx，继续”后才进入下一阶段；修改意见会留在当前阶段继续完善。

## 目录说明

- .agents/skills/：当前生效的 G0–G7 工作流和质量标准。
- knowledge/mathmodel/approved/：已批准的方法卡与论文卡，仅作为候选经验。
- 学习资料/：原始算法与学习材料，不自动当作可靠结论。
- projects/：每道题的独立工作目录，包括保留的历史完整项目。
- deliverables/：最终验收通过后的交付包。
- archive/：旧根目录任务产物、不完整项目与临时隔离资料。
- CATALOG.md：当前项目、交付包、资料库与归档内容的快速索引。
- PROJECT_AUDIT.md：资料审计、调整和保留清单。

根目录只保留工作流、共享运行环境、知识资料与索引文件；具体赛题不得直接放在根目录。

最终交付包至少包含 README.md、MANIFEST.md、REPRODUCE.md、论文 PDF 与可编辑源文件（新项目为 LaTeX）、完整代码与测试、依赖、结果数据、图表及源文件、日志、阶段报告和质量证据表。

## 在 Codex 中使用内容能力

直接说“改进当前模型并验证创新”“根据结果完善论文”“按论文标准重做这张图”，入口按 `AGENTS.md` 路由到阶段技能。模型、实验、主张、图和论文章节通过 `research-evidence` 台账关联；检查器核对登记证据，科研质量仍由真实实验和审阅验证。使用与边界见 [内容能力说明](docs/CONTENT_CAPABILITIES.md)。
