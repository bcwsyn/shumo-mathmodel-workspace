# 数学建模学习工作流人工审批协议

本协议适用于完整数学建模学习工作流及各阶段 Skill。审批门用于让用户学习、检查方向和纠正结果，不把建模责任转移给用户。除非用户明确要求“无需中途确认、连续执行”，默认采用人工审批模式。

## 强制规则

1. 只完成当前已获授权的阶段，不提前生成下游阶段的正式产物。
2. 每个审批点完成后，展示成果并立即停止；未收到明确批准，不得继续。
3. 用户的提问、评价、补充材料或修改意见不等于批准。
4. 只有表达明确继续意图的回复才算批准，例如“批准，继续”“阶段 G1 通过，进入 G2”。
5. 用户要求修改时，保持当前阶段，修改后重新提交审批。
6. 恢复任务时，先读取 `plan.md`、`todo.md` 和已有报告，确认最后一个已批准阶段；不要凭对话记忆猜测状态。
7. 发现题面、数据、规则或结果存在硬风险时，即使用户先前批准，也应指出风险并请求重新确认。

## 审批点

| ID | 审批内容 | 批准后允许进入 |
| --- | --- | --- |
| G0 | 材料盘点、题意理解、子问题与关键歧义 | 建模方案 |
| G1 | 最终建模方案、假设、公式、约束、算法与校验计划 | 最小代码验证 |
| G2 | 最小可行代码、基线结果、可行性与异常检查 | 完整实验 |
| G3 | 完整结果、灵敏度/稳健性、正式数据图表 | 非数据图示或论文规划 |
| G4 | 技术路线图、流程图等非数据图示；也可批准跳过 | 论文大纲 |
| G5 | 论文大纲、章节论点、公式与图表放置计划 | 正文草稿 |
| G6 | 完整论文源文件、摘要、结论、引用和数值核对表 | 预览 PDF |
| G7 | 预览 PDF 的内容与版式 | 最终验收和最终 PDF |

G4 为可选阶段。若不需要非数据图，也必须说明理由并让用户明确批准跳过。

## 每次提交审批的固定格式

```markdown
## 阶段审批

- 阶段：G<编号> <名称>
- 状态：WAITING_FOR_APPROVAL
- 本阶段完成内容：...
- 主要文件：...
- 关键结论或数值：...
- 风险、假设与未决问题：...
- 需要用户决定：...
- 批准后的下一阶段：...

请回复“批准 G<编号>，继续”或列出需要修改的内容。
```

提交上述内容后结束当前轮次。不要在同一轮中开始下一阶段。

## 状态记录

在 `plan.md` 中维护审批表：

```markdown
| 审批点 | 状态 | 批准依据 | 日期/备注 |
| --- | --- | --- | --- |
| G0 | PENDING / WAITING / APPROVED | 用户明确回复 | ... |
```

在 `todo.md` 中将每个阶段拆成“执行”和“用户批准”两个待办。未批准时，下游任务必须保持未开始状态。
