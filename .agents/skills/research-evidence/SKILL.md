# 建模、实验、写作与图表的证据衔接

由当前 Codex 会话执行分析、推导、编码、写作与审阅，本地工具负责计算和编译。无须 Modex App、加密技能或其 API。知识检索按现有工具可用性完成；联网不可用时明确保留文献核验缺口。

## 入口与范围

先确定当前项目、正式输入、主稿和用户授权的阶段。从 `plan.md` 与实际材料判断，保留原 G0–G7 审批协议。局部修改仅处理受影响模型、主张或图，不强制重跑全题。旧项目首次接入先盘点已有证据；未运行实验不得补写成成功。

按任务读取：

- G1 模型深度/创新方案、G2/G3 实验：读取 [modeling-experiments.md](references/modeling-experiments.md)。
- G3 数据图、G4 流程图、G5–G7 写作排版：读取 [writing-figures.md](references/writing-figures.md)。
- 初次建立台账或运行检查：读取 [ledger.md](references/ledger.md)，复制 `assets/research_evidence.json` 到项目 `reports/research_evidence.json`（已存在则增量修改）。空模板不能通过验收。
- Final：读取上述两份内容规范，复核实际证据，再运行全链检查。

## 固定交接

在已有分析/结果/图示/质量报告内补充实质内容，台账只记录定位、关系与哈希，避免重复保存全文。每个阶段将新增或修订的模型、实验、主张、图片、论文章节登记到台账；引用资料核验状态和 AI 参与记录保留在相关报告，不捏造使用工具或模型版本。

使用本机已验证的 Python 3.11+ 绝对路径运行：

```text
<python> -X utf8 <本技能目录>/scripts/check_evidence.py --project <项目绝对路径> --stage G1
```

G1、G2、G3、G4、G5、G6、G7、Final 分别调用同名阶段。G4 显式批准跳过时仍运行检查，台账以 `diagram_waiver` 指向实际批准记录。CLI 只读检查，JSON 输出由调用者收录进阶段报告。退出码 0 表示登记结构/引用/数值关系通过；2 表示错误。`STRUCTURAL_PASS` 绝不是科研、视觉、人工审批或创新水平 PASS。

## 缺陷闭环

每项发现注明证据定位、影响的结论、回到哪个阶段、修复动作和复核结果。缺推导回 G1；实验不足/不公平回 G2/G3；图示失真回 G4；夸大结论/数值错配回 G6；裁切/乱码回 G7。修订源文件后重新执行相关实验或导出，重新核验哈希，不能仅刷新哈希来掩盖证据失效。

程序不会启动实验、判断证明真假、鉴别批准者身份或遍历整篇论文理解语义。执行者须实际读取日志、论文章节和图片。抽查“引用文件虽存在，但内容是否真的支持该主张”；必要时请求另一位队员复核，不能把同一会话的复查称为独立模型评审。
