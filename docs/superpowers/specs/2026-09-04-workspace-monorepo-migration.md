# 数学建模工作区总仓库迁移设计

## 目标

将 `D:\shumo\shumo` 作为唯一 Git 工作区根目录，使工作流、项目、知识库、交付包及正式文档在同一私有 GitHub 仓库中协作。成员在各自本机工作副本中并行修改；GitHub `main` 汇合非冲突改动，成员后续同步后获得共同版本。

## 已核对的起点

- 工作区根目录当前没有 `.git`。
- 唯一内层仓库是 `projects/20260901-CUMCM2020C-credit-decision/.git`。
- 内层仓库远端为 `https://github.com/bcwsyn/2020c-credit-decision.git`，迁移前 `HEAD` 为 `a8422ca1fc3d81f9e09937d758904345a9fd44c6`。
- 内层项目有两张未提交流程图，将纳入总仓库首次基线。

## 迁移方式

采用扁平化总仓库，不采用 Git submodule：

1. 在根目录建立适用于虚拟环境、缓存、日志和临时渲染物的 `.gitignore`。
2. 初始化根目录 Git；先提交迁移设计和忽略规则。
3. 在不移动任何项目内容的前提下，将唯一内层 `.git` 元数据移动到根目录外的带时间戳恢复备份目录；保留远端地址、提交号和标签证据。
4. 将整个根目录正式内容作为总仓库基线加入版本控制；在推送前检查嵌套仓库、超大文件和暂存清单。
5. 创建新的私有 GitHub 总仓库后连接 `origin` 并推送 `main`。旧的信贷项目 GitHub 仓库保留为历史快照，不再作为团队日常同步入口。

## 协作规则

- 每名成员首次克隆总仓库一次；之后可在本机并行修改不同文件。
- “上传本次修改”先同步远端、提交本地改动并推送；不同文件通常自动合并。
- “同步团队最新修改”拉取总仓库 `main`，获得其他成员已经上传的全部非冲突修改。
- 同一 Word、Excel、PDF、Draw.io 或同一文本片段并行编辑可能产生冲突；Codex 必须停止报告，不能猜测覆盖方案。

## 验收

1. 根目录为 Git 仓库，且不存在未声明的嵌套 `.git`。
2. 工作流 `4drawio`、新增的流程图规范、信贷项目及两张新流程图均被总仓库跟踪。
3. `.venv`、缓存、日志和临时文件未被跟踪。
4. 每个大文件均低于 GitHub 单文件限制，或者在推送前单独报告处理方案。
5. 推送完成后，远端 `main` 与本地 `HEAD` 一致。
