# Codex 建模内容能力

在团队总仓库根目录打开 Codex。入口由 `AGENTS.md` 与现有阶段技能触发，科研内容由当前会话生成，本地 Python/绘图工具/XeLaTeX 执行计算、绘图与编译。无需 Modex App 或它的 API；这不是离线大模型，Codex 会话本身仍依赖账号服务。

| 你说的话 | Codex 必须实际做的事 | 可检查产物 |
| --- | --- | --- |
| 改进当前模型并验证创新 | 分析基线缺陷、候选机制、推导、适用条件，随后在授权阶段跑对照/消融 | 模型推导报告、协议、真实代码/日志/指标、否定结果与边界 |
| 加深模型分析 | 校核量纲、约束、可行性/误差、统计解释和复杂度；按题型选验证 | 方程到实现的对应、边界案例、验证计划 |
| 根据已有结果完善摘要/论文 | 定位正式主稿，组织主张、证据、解释和限制，核对数字与引用 | 可编辑章节、数值定位、真实文献和 AI 参与记录 |
| 重做数据图/流程图 | 根据论证选图型，生成源文件、导出，打开检查并迭代 | 数据/图源、正式图、有效 DPI 与视觉报告 |
| 检查这份论文是否证据充分 | 逐项核查模型—实验—主张—图片—正文关系，定位缺陷 | 结构检查结果、人工科学/视觉意见、修复复验记录 |

新题继续使用原来的 G0–G7；这些口令不替代用户已经选定的审批方式。现有论文局部修改只影响必要文件，既有 V9 Word 不自动迁移。旧项目首次接入台账时核对实际文件，缺历史运行证据就标缺失，不能从当前日期倒填历史实验。

## 实际执行入口

能力规范：`.agents/skills/research-evidence/SKILL.md`。

台账空模板：`.agents/skills/research-evidence/assets/research_evidence.json`；复制到具体项目 `reports/research_evidence.json` 后由 Codex 根据真实材料增量填写。字段说明在该技能 `references/ledger.md`。

检查命令（由 Codex 解析绝对路径并执行，队员无需手填）：

```text
<已验证的 python.exe> -X utf8 <仓库>/.agents/skills/research-evidence/scripts/check_evidence.py --project <具体项目> --stage G3
```

程序只读取台账与本地引用文件；阶段选择 G1/G2/G3/G4/G5/G6/G7/Final。成功返回 `STRUCTURAL_PASS`，错误返回 `FAIL` 和退出码 2。不会运行台账里的命令或自动更新证据。

## 验收含义与限制

程序能检查文件缺失/变化、引用断裂、跨项目路径、失败实验充当证据、比较协议不一致、指标未改善却声明支持、登记的正文数字错误、图无可编辑源或没有来源、DPI不足和复核记录未覆盖当前导出物。不会证明数学定理、识别所有夸大句式、检查未登记的正文数字、核验实际网页内容或判断图片美观。真正的科研与视觉验收须运行实验、阅读推导/来源、打开图片及逐页检查 PDF。

采用方案在同一评估协议下比较；同一模型没有提升也能如实完成研究，不能为追求通过而伪造结果。论文数字的自动匹配是显式登记与有限精度对照，不是完整 LaTeX/DOCX 语义解析。

本批新增内容能力与检查器。早先 `workflow/runner.py` 状态调度草稿未作为生产入口接入；团队仍以原 `plan.md` 审批为准。没有自动调用第三方模型评审、没有后台自动运行和没有提交 GitHub。
