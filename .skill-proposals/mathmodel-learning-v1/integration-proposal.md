# 与现有数学建模工作流的集成提案

本提案尚未应用到已安装 Skills。

## 拟安装内容

1. 将候选 Skill 目录安装为 `.agents/skills/mathmodel-learning/`。
2. 将候选知识库安装为项目级 `knowledge/mathmodel/`，使原始材料、候选卡和批准卡与 Skill 指令分离。
3. 保留 `学习资料/` 原样只读，不复制、不改名、不执行其中代码。

## 拟修改 `2analysis-modeling`

在 G0 之后、G1 候选模型比较之前增加“历史知识检索（可选）”：

- 只有项目存在 `knowledge/mathmodel/approved/` 时才检索；无批准卡则跳过，不阻塞建模。
- 先独立完成当前题目的题意、数据、目标和约束分析，再检索，防止被历史论文锚定。
- 输出“历史经验迁移矩阵”：来源、相似点、关键差异、可迁移部分、适用条件、风险。
- 历史材料只能支持候选模型比较，不得替代当前题面证据。
- 迁移矩阵随完整方案一起进入现有 G1，仍由用户确认最终建模方案。

## 拟修改 `1start-mathmodel`

仅在启动说明中补充：若用户希望使用学习库，可先触发 `mathmodel-learning`；草稿知识不会自动用于比赛任务，只有用户批准入库的卡片可作为 G1 参考。

## 不修改的内容

- 不改变 G0–G7 的审批顺序。
- 不允许学习 Skill 越过 G1 直接选定模型或进入代码。
- 不修改 `3coding-visual`、`4drawio`、`5writing`、`6verity` 的现有职责。
- 不把历史论文正文或数值自动写入新论文。
