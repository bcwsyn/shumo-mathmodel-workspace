# 数学建模学习库

把用户提供的优秀论文和算法资料转化为可审查、可追溯、可检索的本地知识库。不要把此过程描述为模型训练或永久记忆；持久知识必须写入知识库文件。

## 路径约定

- 原始资料目录：由用户指定，始终只读。
- 默认知识库：`knowledge/mathmodel/`；用户指定其他位置时以用户为准。
- 使用 `scripts/catalog.py` 生成清单、提取可读文本和执行关键词检索。
- 不把大体积原始 PDF、压缩包或代码集合复制进 Skill 目录。

## 必读参考

- 新建论文学习卡前读取 `references/paper-card-schema.md`。
- 新建算法方法卡前读取 `references/method-card-schema.md`。
- 判断历史方法能否用于新赛题时读取 `references/transfer-checklist.md`。
- 处理来源、版权、不可读格式和批准状态时读取 `references/source-policy.md`。

## 模式 A：学习资料

### L0 资料盘点

1. 递归盘点文件，记录相对路径、格式、大小和 SHA-256。
2. 区分论文、教程、代码、数据、压缩包和不可可靠解析格式。
3. 对 PDF 检查页数与文本可提取性；抽查封面、目录、公式、图表和参考文献页面。
4. 不解压或执行来源不明的程序；只列出安全可读的压缩包目录。
5. 输出不可读或需转换材料清单，不得声称已经学习这些内容。

### L1 生成论文学习卡草稿

对每篇目标论文完整阅读正文、公式、表格、图示和附录，按论文卡模板提炼：

- 题型、子问题依赖与数据特点。
- 模型假设、变量、目标函数、约束和求解算法。
- 模型组合的衔接逻辑，而不只罗列算法名称。
- 基线、误差、灵敏度、稳健性和可复现性。
- 摘要、正文结构、图表表达和写作方式。
- 优点、缺陷、可能不严谨处、适用与不适用条件。
- 可迁移经验及迁移风险。

将草稿写入 `drafts/papers/`，标记 `status: draft`、原始路径和来源哈希。提交用户审批，未批准不得移入 `approved/`。

### L2 生成方法卡草稿

按方法而不是按文件组织知识。合并多份资料中的重复内容，保留来源列表和分歧：

- 解决的问题、输入要求、数学原理与步骤。
- 参数、停止条件、复杂度和实现建议。
- 验证方式、常见错误、失败模式与替代方法。
- 旧 MATLAB/C++ 示例与现代实现之间的差异。
- 只存在代码但缺乏理论说明时，明确标记证据不足。

将草稿写入 `drafts/methods/` 并提交用户审批。

### L3 批准入库

只有用户明确回复批准后，才将对应草稿移入 `approved/papers/` 或 `approved/methods/` 并更新索引。用户的提问、修改建议或一般好评不等于批准。

## 模式 B：应用到新赛题

1. 先独立理解当前题目，避免被历史论文锚定。
2. 按题型、数据、目标、约束和评价方式检索已批准知识；草稿只能作为未验证线索。
3. 最多优先加载最相关的少量卡片，不一次性加载整个知识库。
4. 输出历史经验迁移矩阵：来源、相似点、差异、可迁移部分、前置条件和风险。
5. 给出候选模型，不直接替用户决定最终方案。
6. 新赛题的题面、附件和实际数据始终优先于历史经验。
7. 不复用历史论文的实验数值、结论措辞或不可核验参考文献。
8. 把检索结果交给 `2analysis-modeling` 的 G1 审批，不越过建模审批门。

## 输出要求

- 每个结论可追溯到原始文件和页码或代码路径。
- 清楚区分“来源内容”“Codex 评价”“可迁移建议”。
- 不大段复制论文原文；以结构化概括为主。
- 对扫描件、乱码、公式提取失败和缺页明确降级置信度。
- 输出内容涉及未知或过时规则时，要求核对当年官方规则。

## 常用命令

```powershell
python scripts/catalog.py scan --source "<资料目录>" --library "<知识库目录>"
python scripts/catalog.py search --library "<知识库目录>" --query "预测 时间序列 灵敏度"
```

不得自动执行压缩包中的脚本、宏、二进制文件或 MATLAB 程序。
