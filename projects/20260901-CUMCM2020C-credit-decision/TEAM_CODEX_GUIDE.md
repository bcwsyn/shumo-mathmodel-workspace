# 队员 Codex 同步指南

本项目的唯一共享源是私有 GitHub 仓库：

`https://github.com/bcwsyn/2020c-credit-decision`

在开始前，请确认你已经在 GitHub 接受仓库协作者邀请。GitHub 登录、密码、验证码和授权页面必须由你本人完成；不要把凭据发给 Codex。

## 第一次使用

把下面这段话直接发给你的 Codex：

> 请把私有仓库 `https://github.com/bcwsyn/2020c-credit-decision` 克隆到本机合适的工作目录。克隆完成后，先完整阅读仓库根目录的 `TEAM_CODEX_GUIDE.md`，不要修改或上传任何文件。请报告当前分支、最新提交号、根目录文件列表，并确认 `README.md`、`MANIFEST.md`、`code/`、`paper/`、`results/` 与 `inputs/` 是否可读。

这一步是你的读取验收。把 Codex 的报告发给队长即可，无需为了验收创建提交。

## 日常读取

当你希望获得团队已上传的最新版本时，对 Codex 只说：

> 同步团队最新修改

Codex 应自动检查本地工作区并同步远端 `main`，随后报告新增提交与改动摘要；它不提交或上传任何文件。如本地有未提交改动、发生合并冲突或认证失败，Codex 应停止并说明原因，不能覆盖本地文件。

## 上传自己的修改

完成工作且确认需要共享时，对 Codex 只说：

> 上传本次修改

Codex 应自动检查当前修改、获取远端 `main` 的最新版本、创建能概括变更的提交并推送。遇到认证失败、合并冲突，或存在无法安全判断是否属于项目内容的文件时，Codex 应停止并报告，不能覆盖远端内容。只有明确说“上传本次修改”才授权 Codex 推送到 GitHub。

## 共同规则

- 不使用 `git push --force`、`git reset --hard`、`git checkout --` 等可能覆盖他人工作的命令。
- 不上传 `.venv/`、缓存、临时目录、日志或 `deliverables/` 重复交付包；这些已由 `.gitignore` 排除。
- `code/`、`paper/`、`figures/`、`results/`、`reports/` 和 `inputs/` 是共享项目内容。修改模型、结果或论文数字后，必须同步相应的代码、结果与说明。
- Word、PDF、Excel 与 Draw.io 文件无法可靠地逐行合并；同一时间仅一名成员修改同一文件。开始修改前先在群内说明文件名。
- 如果 Codex 报告合并冲突，不要让它猜测保留哪一方。将冲突文件、双方修改意图和 Codex 报告发给队长后再处理。

## 常见状态

| Codex 报告 | 含义与处理 |
| --- | --- |
| 仓库未找到或 403 | 检查是否接受 GitHub 邀请、是否登录正确账号。 |
| 认证失败 | 由本人完成 GitHub 登录或 Git 凭据授权，不能向 Codex 提供密码或令牌。 |
| 本地有未提交改动 | 先决定保留、提交或放弃这些改动，再请求同步。 |
| 合并冲突 | 停止同步，交给队长确认保留方案。 |
| 推送成功 | 将提交号与 Codex 生成的改动摘要发到团队群，其他成员再执行“同步团队最新修改”。 |
