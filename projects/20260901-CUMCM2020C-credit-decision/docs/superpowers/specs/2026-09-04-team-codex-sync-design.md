# 团队 Codex GitHub 同步：极简设计

## 目标

让已获 GitHub 私有仓库访问权的队员无需学习 Git 工作流；队员只需向自己的 Codex 下达“读取最新团队修改”或“上传当前修改”等自然语言指令。Codex 负责执行相应的 Git 操作、解释结果，并在冲突时停止。

## 范围

- 在仓库根目录新增 `TEAM_CODEX_GUIDE.md`，供队员及其 Codex 阅读。
- 以 `main` 作为唯一共享分支；不引入任务系统、分支规范或代码评审流程。
- 对仓库做一次全新临时克隆，验证私有仓库的基线可读取。
- 队员接受 GitHub 协作者邀请后，由其 Codex 完成一次读取验收并在对话中报告结果。

## 不在范围内

- 不修改模型、论文、图表、输入、结果或复现逻辑。
- 不自动授予更多人员权限，也不替队员接受 GitHub 邀请。
- 不要求队员在本机直接输入 Git 命令。

## 操作约定

### 读取

队员说“读取 GitHub 团队最新修改”时，其 Codex 应先获取远端更新，再以只读方式报告当前分支、最新提交、改动摘要和关键目录是否存在。读取不得写入、提交或推送任何文件。

### 上传

队员说“上传当前修改，说明：优化流程图”时，其 Codex 应依次检查工作区改动、拉取远端更新、在无冲突时提交并推送。若发现同一文件的合并冲突、未解释的大范围二进制改动或推送失败，必须停止并报告原因，不能覆盖远端内容。

### 文件边界

`.gitignore` 已排除虚拟环境、缓存、临时目录、日志与重复交付包。`code/`、`paper/`、`figures/`、`results/`、`reports/` 与 `inputs/` 属于共享项目内容。Word、PDF、Excel 和 Draw.io 文件是二进制或图形文件，同一时间只应由一名成员修改同一文件。

## 队员端读取验收

队员的 Codex 必须报告：仓库地址、当前提交号、当前分支、根目录结构，以及 `README.md`、`MANIFEST.md`、`code/`、`paper/`、`results/` 与 `inputs/` 是否可读。验收结果只需在队员与其 Codex 的对话中回传给队长，无需为验证专门提交文件。

## 验证与失败处理

维护者的全新临时克隆应能检出 `main` 与 `baseline-2026-09-04` 标签。队员未接受邀请、未配置 GitHub 登录或没有仓库权限时，Codex 应明确报告认证/授权阻塞，不得转而访问其他仓库或更改权限。
