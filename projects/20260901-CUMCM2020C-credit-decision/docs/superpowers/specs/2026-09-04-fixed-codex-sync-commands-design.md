# 固定 Codex 同步口令设计

## 目标

将团队 GitHub 协作简化为两句自然语言口令：`上传本次修改` 和 `同步团队最新修改`。队员无需手写 Git 命令、提交说明或远端地址。

## 行为约定

- `上传本次修改`：Codex 检查当前工作区变更，先获取并合并远端 `main` 的最新提交，再只提交可识别为项目内容的当前修改，并推送至 `main`。提交标题由 Codex 根据变更自动生成。
- `同步团队最新修改`：Codex 检查本地工作区是否干净；干净时拉取远端 `main` 并报告新增提交与改动摘要。它不创建提交、不推送、不改写用户本地未提交内容。
- 遇到 GitHub 认证、远端合并冲突、本地未提交改动阻碍同步，或有无法安全归类的文件时，Codex 停止并说明原因，不覆盖、不删除，也不使用强制推送或重置命令。

## 共享与边界

GitHub `main` 是唯一共享版本。成功上传后，其他队员各自在本机执行 `同步团队最新修改`，其工作副本才会获得这次变更；同步不会实时自动发生。

Word、PDF、Excel 和 Draw.io 等二进制或难合并文件需要在团队中约定单人编辑，避免并行修改同一文件。

## 验收

更新后的 `TEAM_CODEX_GUIDE.md` 必须：

1. 明确写出两句固定口令；
2. 不再要求用户填写提交说明；
3. 明确上传与同步的自动动作及停止条件；
4. 保留 GitHub 登录由用户手动完成、不得提供凭据给 Codex 的要求。
